M365

Non-technical · Microsoft Copilot

Good materials: a sanitized Jira export, a small source pack, a sample spreadsheet, or approved meeting notes.

Lab idea 01 · Jira to presentation

Turn scattered tickets into a clear story

Strong starter

Scene: A project update is due, but status, blockers, owners, and dates are spread across Jira issues.

Try

Give Copilot a small approved export or curated issue pack. Ask it to identify missing context before drafting.

Leave with

A one-page update and a 3-slide presentation outline, with each claim traceable to a ticket.

  1. Set audience + reporting period
  2. Build a fact / source list
  3. Draft, critique, refine

Review: Are blockers and unknowns visible? Can a reader trace dates, owners, and status back to the source?

Lab idea 02 · Notebook to document

Build a useful guide from a source pack

Strong starter

Scene: A teammate needs a reliable how-to from several approved project documents, not another long chat answer.

Try

Collect the right sources, ask focused questions, identify gaps, then iterate the guide for its intended reader.

Leave with

A one-page guide with steps, exceptions, source links, and unanswered questions.

  1. Choose sources
  2. Ask before drafting
  3. Check, then simplify

Review: Is each important instruction supported? Did the rewrite make the guide clearer without losing a caveat?

Lab idea 03 · Excel to action

Find the exceptions, explain the pattern

Strong starter

Scene: A spreadsheet has a backlog, correspondence log, or workload estimate that takes too long to scan manually.

Try

Ask what the columns mean, look for overdue or unusual rows, and request a concise explanation with the method shown.

Leave with

A checked exception list and a short manager-ready summary of what needs attention.

  1. Clarify the question
  2. Inspect the calculation
  3. Verify selected rows

Review: Do filters, formulas, and sample rows support the summary? What can the data not tell us?

Lab idea 04 · Teams to follow-up

Turn meeting notes into owned actions

Alternate

Scene: A useful meeting ends, but decisions and next steps disappear into a transcript and a busy inbox.

Try

Extract decisions, owners, due dates, and open questions; draft a follow-up in the right tone.

Leave with

An action register and a review-ready email, not an automatically sent message.

  1. Separate decision from idea
  2. Flag missing owners
  3. Review before sending

Review: Did Copilot invent an owner, deadline, or commitment? Are transcript access and meeting settings appropriate?

Microsoft tool notes

Try the experience participants actually have: Copilot Chat, Word, Excel, PowerPoint, or Teams. Copilot Notebooks and Pages are good source-and-document exercises when enabled. For Jira or Confluence, use an approved connector only if confirmed; otherwise bring a sanitized export. Verify licenses, tenant settings, source permissions, and sharing before the workshop.

GH

Technical · GitHub Copilot

Good materials: a small sandbox repository, one bounded Jira issue, a known test gap, and a seeded pull-request diff.

Lab idea 01 · Ticket to tested slice

Turn a Jira request into a small, checked change

Strong starter

Scene: A short Jira ticket leaves implementation details open, and the developer needs to turn it into a safe plan before coding.

Try

Collect ticket + repo context; write acceptance criteria and open questions; plan; implement one small slice; run checks.

Leave with

A reviewable diff, meaningful tests, and a short note explaining assumptions and evidence.

  1. Ask for missing context
  2. Spec before code
  3. Test and inspect diff

Review: Did the code meet the acceptance criteria? Which assumption should have been a question?

Lab idea 02 · CLI + skill + Jira

Close the ticket loop from the console

Strong starter

Scene: The change is done, but the ticket still needs a useful update grounded in actual code and test results.

Try

Use a team skill to gather issue, diff, and test context; draft a Jira comment; preview it; require a person to approve any write.

Leave with

A reusable skill outline and a safe console workflow: read → summarize → preview → approve → update.

  1. Start read-only
  2. Show a dry run
  3. Human approves write

Review: Is every claim backed by a test or diff? Could the skill accidentally post secrets or overwrite a useful update?

Lab idea 03 · Adversarial code review

Review a pull request like a skeptic

Strong starter

Scene: A pull request looks plausible, but it contains one real defect and one tempting false alarm.

Try

Give Copilot the diff, ticket criteria, and test output. Ask for prioritized findings with evidence, impact, and a verification idea.

Leave with

A review that distinguishes a real issue from speculation and names the missing test.

  1. Find evidence in diff
  2. Challenge each finding
  3. Verify before accepting

Review: Were findings actionable and correct? Did the reviewer miss a security or behavior regression?

Lab idea 04 · Models and loops

Compare models on one real task

Alternate

Scene: The team debates which model is best, but has no shared task or review criteria.

Try

Run the same bounded task with two available models. Use `/goal` to keep the objective explicit and `/loop` to iterate on checks if supported.

Leave with

A small scorecard for correctness, test quality, review effort, latency, and usage limits.

  1. Same prompt + context
  2. Same acceptance tests
  3. Compare reviewed output

Review: Which model helped this task, under these constraints? Avoid declaring a universal winner.

CLI + skill boundary

GitHub Copilot CLI provides the assistant workflow; Jira access comes from a separately approved Jira CLI, MCP server, API, or connector. Keep the exercise read-only or in a sandbox first, preview every change, and require explicit approval before posting. Check the installed CLI's help for `/goal` and `/loop`; command availability and behavior vary by version and configuration.

Good 12-minute setup

Tell a specific work story: what is slow or unclear today, what data is available, where AI may help, and what a successful result looks like. Keep the pitch grounded in the group's own tasks.

Keep the room safe

Use synthetic or sanitized material. Do not connect customer systems or enable write actions just for a demo. Keep legal, financial, security, and code-approval decisions with qualified people.

Facilitator setup checklist

Confirm the exact Copilot licenses and feature availability; prepare a no-login fallback dataset; create a sandbox Jira project and repository if using integrations; check CLI commands and skill loading on the training machines; seed one correct answer and one realistic failure; define the review rubric before the session.
